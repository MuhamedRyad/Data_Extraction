# Generic Data Extraction Feature — v0.3.0

**Scope: extraction only.** No chunking, vector store, retrieval, RAG, agent orchestration, summaries, embeddings, or document indexing.

The feature accepts one file and returns (1) a **pre-extraction manifest** telling you where text, tables, and images appear and (2) a **structured extraction result**, with source coordinates, extraction method, route explanation, and quality warnings.

## v0.3.0 — Ordered, source-aware extraction JSON contract

This version adds rich **extraction provenance**, not chunking logic. `inspect()`
and `extract()` produce the **same deterministic page and region sequence**.

- `schema_version`: `extraction.v0.3` (returned by both inspect and extract).
- `manifest.pages[].number`: original **one-based PDF physical page number**; sheets
  and DOCX logical documents are clearly identified by `kind` rather than
  misrepresented as physical pages.
- `document_order_region_ids`: stable cross-page ordered region references.
- `pages[].reading_order_region_ids`: stable page-local ordered region references.
- `regions[].position`: `page_number`, `reading_order_index`,
  `document_order_index`, `source_stream_index` (only when available),
  `reading_order_quality`, original `bbox`, normalized `bbox`, coordinate system.
- `regions[].relations`: spatial overlapping region IDs, native text overlay
  detection, `region_role`, and nullable parent (not guessed).
- `regions[].kind` / `regions[].content_type` **is the extracted content**;
  `provenance.original_region_kind` **is the physical input**. For example,
  OCR text from a scanned page is `text` **from** `image`.
- `regions[].provenance`: `source_surface` (native PDF text, PDF table, page
  render, embedded PDF image, Word content, spreadsheet, etc.), extraction
  method, exact available provider and model ID, attempted methods, source
  checksum, region image role, whether native text was masked, SHA-256 of the
  processed source raster if present. Provider/model ID is `null` when unknown.
- `regions[].table_details`: rows, columns, shape, empty cell count, and two
  explicit false flags indicating that merged-cell geometry and header role
  have **not** been independently established. The original table matrix,
  including blank cells, remains in `table`.
- `requires_review` and `review_reasons`: image extraction, OCR numeric
  fields, uncertain raster table structure, or material overlapping regions
  are not quietly approved. `ready_for_publication` is a **legacy field name**
  meaning an extraction-level quality/handoff gate, not indexing or publishing.

**Important reading-order caveat:** PDF `reading_order_index` is a **deterministic
geometric estimate** in this version, not guaranteed semantic reading order for
multi-column/rotated layouts. Overlapping content is marked
`ambiguous_overlap`, forcing review. Small bounding-box collisions from
consecutive Arabic lines are ignored if the overlap occupies less than 40% of
the smaller bbox. For DOCX, paragraph/table sequence follows document flow,
but inline images can be approximate and physical pagination is unknown.

**Scope guard:** no chunking, embeddings, RAG, semantic indexing, or document
summaries are produced by this feature. This metadata is intentionally rich so
independent downstream systems can choose their own processing strategies.

## Pipeline

```text
DocumentInput (file name, bytes, source_id)
   -> ValidateUpload (size, format, ZIP limits)
   -> DetectFileAction (file signature)
   -> InspectFileAction (page/sheet / region / layout hint, no OCR or model)
       Page 1: Text [native], Table [native]
       Page 2: Image [possibly a scanned table]
       Page 3: Text [native], Image [native-text overlay]
   -> DispatchRegionsAction
       TEXT  -> ExtractTextAction -> native text with anchor
       TABLE -> ExtractTableAction -> 2D cells, empty cells preserved
       IMAGE -> ExtractImageAction
          normal image: OCR -> confidence gate -> optional Vision fallback
          raster grid: optional Vision structural extraction first -> OCR fallback
          native-text overlay: white-mask native text areas before OCR; review mandatory
   -> ExtractionResult
       pages[].regions[] = type of extracted content + source kind
       method / attempted_methods / route_reason / bbox / review_reasons
       ready_for_publication (legacy name, **only** an extraction-level handoff gate)
```

**Inspect does not invoke OCR or Vision.** It may render images at configured DPI and conservatively inspect pixel patterns to flag a `raster_grid_table` hint. It cannot guarantee a borderless/scanned table will be detected without OCR/Vision.

## Previous improvements in v0.2.0

1. **Raster grid hints**: detect rectangular table borders in image/PDF/DOCX regions using local deterministic pixel analysis (Pillow, without LLM/OCR). `content_hint=table` remains a hint; original region stays `kind=image` in the manifest.
2. **Layout-aware dispatch**: `AUTO` routes scanned table candidates to Vision **first if a provider and call budget exist**, then falls back to OCR if the model doesn't return structured cells. Plain images start with OCR. No fabricated cells from OCR text.
3. **Source type vs extracted content**: `ExtractedRegion.source_kind=image` and `ExtractedRegion.kind=text` for OCR text; `kind=table` when cells were extracted. `page.content_types` in the final result describes extracted content, whereas the manifest shows source regions.
4. **Native overlay masking**: instead of discarding a whole image when it intersects native text, mask the native text rectangle in the raster sent to OCR; flag the result `masked_native_overlay_requires_review` because obscured pixels may contain additional content.
5. **Auditable routes**: `route_reason` and `attempted_methods` on every extracted region. Example: `raster_table_vision_first` or `ocr_insufficient_vision_fallback`.
6. **Output quality**: invalid OCR confidence does not pass the auto-accept gate. OCR raster-table text, irregular model cells, model outputs, and OCR numeric/ID values require review.
7. **Resource controls**: DOCX embedded images have image count/pixel budgets and are decoded/re-encoded as PNG before OCR/Vision.
8. **Regression testing**: 31 passing tests (19 carried forward, 12 new); real Arabic 5-page sample benchmark run using locally installed Tesseract.

## Quick start

```bash
python -m pip install -e ".[ocr,dev]"
python -m pytest -q
python run_demo.py /path/to/sample.pdf --action inspect
python run_demo.py /path/to/sample.pdf --action extract --ocr
```

For real OCR, install the Tesseract binary and Arabic/English language data (`ara+eng`). The code doesn't send files to cloud services unless you explicitly inject an external VisionProvider.

```python
from pathlib import Path
from data_extraction import DataExtractionService, DocumentInput, TesseractOCRProvider

path: Path = Path("scan.pdf")
source: DocumentInput = DocumentInput(
    file_name=path.name,
    content=path.read_bytes(),
    source_id="tenant-a:scan-1",
)
service: DataExtractionService = DataExtractionService(
    ocr_provider=TesseractOCRProvider(language="ara+eng"),
)
manifest = service.inspect(source)
for page in manifest.pages:
    print(page.number, [(r.kind, r.content_hint, r.bbox) for r in page.regions])

extracted = service.extract(source)
for page in extracted.pages:
    for region in page.regions:
        print(page.number, region.source_kind, region.kind,
              region.route_reason, region.attempted_methods,
              region.requires_review, region.review_reasons)
```

## Existing contracts / formats

| Source | Page number semantics | Parsing strategy |
|---|---|---|
| PDF | **Physical** page | PyMuPDF native text, table detection, image regions + pixel-grid hints |
| DOCX | One **logical document** | Paragraphs/tables/inline images, no physical page positions |
| XLSX | **Worksheet** number | All cells/formulas preserved as strings or null |
| CSV | One **logical document** | CSV dialect + all rows/cells |
| TXT/MD/JSON/HTML/XML | One **logical document** | Raw UTF-8 content; DOM/JSON semantic extraction not implemented |
| PNG/JPEG/WebP | One **image** | OCR/model routing, grid hints |

`bbox=(x0,y0,x1,y1)` uses PDF points for PDF and pixels for image files. DOCX/CSV/TXT/XLSX have no reliable page-space bbox. Raw image bytes are kept in internal candidates only, not output contracts.

## OCR vs Vision Routing

| Input | AUTO choice | Fallback / issue |
|---|---|---|
| Native text | Native | None |
| Native table | Native | Structural review when irregular |
| Plain image | OCR | Vision for empty/low-confidence OCR if configured and budget available |
| Raster image with table-grid hint | Vision structured table first (if configured) | OCR text fallback, marked `raster_table_structure_not_reconstructed` |
| Image with native text overlay | OCR on masked image pixels | Mark `masked_native_overlay_requires_review` |
| Image while OCR and Vision not configured | Unresolved | No invented result |

`VisionProvider` is a Protocol, not a real model implementation. It must return `ProviderTextResult(text, confidence, structured_table)`. The caller controls any API billing, permissions, transport security and data policy. `max_vision_calls` is enforced per `extract()` call. `VISION_ONLY`, `OCR_ONLY` and `DISABLED` override AUTO.

## Limits / next engineering gates (still extraction only)

- Borderless tables, handwriting, stamps, rotated/multicolumn documents, merged tables, charts and decorative images need measured layout/vision performance. The raster grid detector is a conservative *hint*, not general-purpose image understanding.
- Masking native overlays prevents simple repeated OCR of native words, but can hide other raster information under the same rectangle; these regions are never auto-approved.
- DOCX uses logical document positions, not rendered page numbers. Physical pages require a renderer/conversion step, not guessed labels.
- Native tables are output as cell matrices; merged-cell geometry and rowspan/colspan are **not** yet represented as first-class metadata.
- Add controlled production-grade ModelGateway adapter with schema validation, rate limits, tenant-scope and model cost limits, plus structured table extraction.
- Measure `text_exact_match`, `field_exact_match`, `table_cell_accuracy`, `region_recall`, `reading_order_accuracy`, `false_auto_accept_rate`, latency/cost on a labeled corpus. Do not claim 100% from successful region coverage.
- Add parser isolation, security scanning, untrusted-file sandboxing, sensitive-data policy, and streaming for large inputs.

No implementation of RAG, chunking, retrieval or indexing belongs in this feature.
